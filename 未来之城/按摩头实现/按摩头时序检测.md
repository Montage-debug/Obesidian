# 按摩头管理器系统设计文档

## 概述
本文档详细描述了按摩头管理器的完整系统设计，包括识别命令发送、时间累积、超时机制和心跳检测等所有时序相关的设计。

## 系统架构

### 核心组件
1. **MassageHeadManageNode** - 主节点，负责协调所有功能
2. **ProtocolV1** - 协议实现，处理数据包解析和命令生成
3. **MassageHeadManager** - 协议管理器，提供统一接口
4. **DatabaseManager** - 数据库管理，存储设备配置

## 识别机制设计

### 识别命令发送时序

#### 1. 上电快速识别（仅一次）
- **触发时机**: 节点启动后500ms
- **命令**: `createIdentifyCommand(0x01)`
- **目的**: 捕获设备自动发送的识别数据
- **日志**: "上电快速识别：发送识别命令"

#### 2. 常规识别（持续）
- **周期**: 3秒
- **命令**: `createIdentifyCommand(0x01)`
- **目的**: 检测设备插拔状态
- **处理流程**:
  ```
  定时器触发 → 发送识别命令 → 等待响应 → 更新设备状态
  ```

### 识别数据包格式
```
发送: 5A A5 05 82 10 01 00 01
返回: 5A A5 06 83 10 01 01 00 [手柄ID]
```

### 识别状态机
```
状态图:
┌─────────────┐     收到识别包      ┌─────────────┐
│   离线      │ ──────────────────→ │   在线      │
│  is_online  │                       │  is_online  │
│   = false   │                       │   = true    │
└─────────────┘                       └─────────────┘
      ↑                                    │
      │          5秒无响应                  │
      └─────────────────────────────────────┘
```

## 时间累积机制

### 累计用时读取
- **周期**: 60秒（1分钟）
- **命令**: `createUsageTimeReadCommand()`
- **返回格式**: `5A A5 06 83 10 09 01 [高位] [低位]`
- **数据解析**: `usage_time = (high_byte << 8) | low_byte` (分钟)

### 时间累积流程
```
设备上线 → 启动60秒定时器 → 发送读取命令 → 解析响应 → 更新累计时间
```

## 超时机制设计

### 超时参数配置
```cpp
// protocol_v1.hpp
static constexpr double OFFLINE_TIMEOUT = 5.0;    // 5秒离线检测
static constexpr double HEARTBEAT_TIMEOUT = 12.0; // 12秒心跳超时
```

### 超时检测逻辑
```cpp
bool ProtocolV1::checkDeviceOnline()
{
    auto now = clock_->now();

    // 1. 心跳超时检测（优先）
    double heartbeat_elapsed = (now - last_heartbeat_time_).seconds();
    if (heartbeat_elapsed > HEARTBEAT_TIMEOUT) {
        RCLCPP_WARN("设备心跳超时（%.1f秒）", heartbeat_elapsed);
        resetStatus();  // 重置所有状态
        return false;
    }

    // 2. 普通数据包超时检测
    double elapsed = (now - last_packet_time_).seconds();
    if (elapsed > OFFLINE_TIMEOUT) {
        RCLCPP_WARN("设备超时未响应（%.1f秒）", elapsed);
        resetStatus();  // 重置所有状态
        return false;
    }

    return true;
}
```

### 时间戳更新策略
1. **`last_packet_time_`**: 任何有效数据包到达时更新
2. **`last_heartbeat_time_`**: 主动查询响应时更新

## 心跳机制设计

### 心跳定时器配置
- **周期**: 3秒
- **触发条件**: 设备在线（handle_id > 0）
- **串口状态**: 必须打开

### 心跳查询策略
```cpp
// 智能查询策略
if (设备支持温度) {
    发送温度读取命令  // 最轻量级查询
} else if (设备支持电机) {
    发送电机状态查询命令
}
// 不支持的设备：仅依赖识别包
```

### 心跳查询命令
```cpp
// 温度读取（首选）
auto temp_cmd = protocol_->createTemperatureReadCommand();
// 格式: 5A A5 05 82 10 06 00 01

// 电机状态查询（备选）
auto motor_cmd = protocol_->createMotorControlCommand(current_state);
// 格式: 5A A5 05 82 10 07 00 [状态]
```

### 心跳工作流程
```
心跳定时器(3秒) → 检查设备在线 → 选择查询命令 → 发送命令 → 等待响应
     ↑                                                    ↓
     └─────────── 更新last_packet_time_ ───────────────┘
```

## 串口数据接收处理

### 数据接收流程
```
串口数据到达 → processSerialData() → 提取完整包 → onSerialData() → 解析处理
```

### 数据包处理时序
1. **数据累积**: 接收数据追加到`receive_buffer_`
2. **包头查找**: 寻找`0x5A 0xA5`
3. **长度检查**: 确保有足够数据确定包类型
4. **包提取**: 根据功能码提取定长数据包
5. **数据处理**: 通过回调函数处理完整包

### 粘包和断包处理
```cpp
// 处理策略
while (还有数据) {
    查找包头;
    if (找到包头) {
        if (数据足够) {
            提取完整包;
            处理数据包;
            更新处理位置;
        } else {
            保留数据，等待更多;
            return;
        }
    } else {
        清除无效数据;
        return;
    }
}
```

## 错误处理与恢复

### 串口错误处理
```cpp
try {
    size_t bytes_read = serial_driver_->port()->receive(buffer);
    // 处理数据...
} catch (const std::exception& ex) {
    if (错误包含"Bad file descriptor") {
        // 设备断开，清理资源并重连
        关闭串口();
        重置驱动对象();
        尝试重连();
    }
}
```

### 重连机制
- **最大重试次数**: 3次
- **重试间隔**: 1秒（递增）
- **失败处理**: 等待5秒后重新开始
