```c
# 给这块 ESP32 写入设备身份（NVS），并算出该设备专属的 MQTT 密钥
./tools/provision-device.sh --port /dev/ttyACM0 --sn robot01

# 内部调用 `provision-device.py`
# 脚本执行流程
#1. 读芯片 MAC
#   esptool --port /dev/ttyACM0 read_mac
#   → 例如 80:f1:b2:d2:f4:46

#2. 用产线主密钥派生设备 key
#   key = HMAC-SHA256(factory_master.key, "robot01|80f1b2d2f446")

#3. 生成 NVS 镜像（命名空间 device）
#   sn       = robot01
#   key      = 上面算出的 64 位 hex
#   mac_bind = 当前芯片 MAC（6 字节）

#4. 烧录到 Flash 的 NVS 分区（0x9000）
#   只写 NVS，不重烧整个固件

#5. 打印 Broker 注册提示
#   mosquitto_passwd / ACL 该怎么配
脚本会打印 `sn` 和 64 位 hex 的 `key`
```

```c

另开一个终端：

mosquitto_pub -h 192.168.10.121 -p 1883 \
-u controller -P '0' \
-t 'wlzc/robot01/cmd' -m poweron

# 关机
mosquitto_pub -h 192.168.10.121 -p 1883 \
-u controller -P '0' \
-t 'wlzc/robot01/cmd' -m shutdown
```

```c
常见问题
| 现象 | 处理 |
|------|------|
| `1883 address already in use` | `sudo systemctl stop mosquitto && sudo systemctl disable mosquitto` |
| `docker compose` 报权限错误 | 执行 `newgrp docker` 或重新登录 |
| 改密码后连不上 | `docker compose restart mosquitto` |
| ESP32 CONNACK 5（未授权） | 检查 `add-device.sh` 的 sn/key 是否与 NVS 一致 |
| PC 能连、ESP32 不能连 | 检查防火墙：`sudo ufw allow 1883/tcp` |
| 容器 Up 但无消息 | `docker compose logs mosquitto` 查错误 |
| 订阅无输出 | 确认设备已烧录、已配对、网线连通、Broker IP 正确 |
```
