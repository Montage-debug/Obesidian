# /asu-resume：酥化经历并复刻同款简历

用户输入 `/asu-resume`、`$asu-resume` 或“我要阿酥同款简历”时使用本技能。先区分已有稿迭代与从模板新建。

## 本地资源与模式

- **已有稿迭代**：先读工作空间根目录的 `workspace-state.json`，使用用户指定稿或登记的基线。保留版式及未要求修改的内容，新岗位稿默认复制到独立版本目录。可使用根目录 `scripts/resume_workspace.py new` 创建当前编辑器的副本。
- **从模板新建**：先检查工作空间根目录 `assets/asu-resume-template.html` 是否存在；存在时作为只读母版复制。按 [references/asu-resume-template.md](references/asu-resume-template.md) 排版。
- **原始母版缺失**：明确告知“原始 ASu 母版未随技能提供”。已有稿可继续迭代；无可用稿时根据版式说明制作 ASu 风格后备 HTML，交付时说明不能保证原版复刻精度。需要精确复刻且没有可用参考时，说明所缺资源。
- 当前附件的 `assets/` 仅含简历照片；不要假定 Logo、通用图标库和 18 套通用模板已安装。参考文档中的资源清单是目标布局，不是存在性证明。
- 不修改只读母版，不将真实身份信息写进共享模板。根据内容及用户要求确定页数，不因模板示例固定为两页。

## 工作流程

0. 按上述模式选择并复制真实存在的编辑起点，已有稿小改不重新套模板。
1. 读取用户提供的简历、PDF、截图或项目材料，提取真实姓名、联系方式、教育、经历、项目、技能和公开链接。
2. 先把经历改写成“目标身份 → 项目全景 → 个人职责 → 技术动作 → 结果证据”，再排版；不把截图直接嵌入简历。
3. 仅在工作空间根目录 `assets/logos/` 中对应文件存在时使用公司/平台 Logo；找不到时使用文字条，不要臆造 Logo。
4. 生成真正可编辑的 HTML。新建完整编辑器时提供页面模式、文字格式、撤回/前进、照片替换、保存 HTML 和打印入口；已有稿仅按用户范围迭代，对缺失功能如实说明。通用图标缺失时使用文字标签。副本使用独立 localStorage 键，照片使用有效相对路径或嵌入数据。浏览器自动保存不等于磁盘文件更新。
5. 导出时按 `../resume/SKILL.md` 的 Print-preview QA 与 PDF 验收要求检查；尤其检查固定页面高度和 overflow:hidden 是否隐藏正文。没有生成并验证 PDF 时，不声称已交付 PDF。每版记录来源、修改要点、待确认事实和验证结果。

## 图标规则

生成 AI、模型、平台或公司图标时，优先遵循 [LobeHub Icons 技能说明](https://lobehub.com/icons/skill.md)，使用 `@lobehub/icons` 或 `@lobehub/icons-static-svg` 的 SVG/CDN 资源。不要手绘已有品牌图标，也不要用低清截图替代可缩放资源。新增 Logo 时登记到 [references/asu-resume-template.md](references/asu-resume-template.md) 的 Logo 表。

电话、邮箱、微信、身份、教育和 Star 等通用图标在资源可用时使用 SVG，否则用文字标签，不使用 Emoji。照片使用用户提供的真实图片，未提供时留空；已有稿是否支持点击替换，以实际功能为准。

## 内容边界

- 保留正式职位、公司、时间和教育背景；不通过模板制造更高职级。
- 每个“Owner、主导、架构、0→1、核心作者”都必须有职责、提交、上线或评审证据。
- 项目总调用量、用户数、Star/Fork 等指标要标明口径，不能自动算成个人成果。
- 不确定的信息使用 `【待补：指标/职责/链接】` 标记，成稿前集中让用户核对。

## 与 `/asu` 的配合

用户只说“我要酥化”时，可以先输出简历内容和 HR 开场白，不强制生成 HTML。用户明确说“复刻同款”“我要阿酥同款简历”“做简历文件”或输入 `/asu-resume` 时，再按本技能的资源与模式选择编辑起点，生成用户专属可编辑简历文件。
