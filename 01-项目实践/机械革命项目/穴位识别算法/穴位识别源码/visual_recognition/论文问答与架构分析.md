## 问题1：穴位数据集是什么格式？

你的穴位数据集**不是**标注好点位的LabelMe JSON文件，也不是打好点位的图片。而是**加密的JSON配置文件**（`.enc`文件），存储在 `visual_recognition/acu_config/` 目录下：

| 文件 | 大小 | 对应部位 |
|------|------|---------|
| `acupoints_config.enc` | 35 KB | 背部穴位配置 |
| `abdomen_acupoints_config.enc` | 11 KB | 腹部穴位配置 |
| `leg_acupoints_config.enc` | 4 KB | 腿部穴位配置 |

这些文件使用 **Fernet 对称加密**（密钥硬编码在 `draw_point.py` 中：`FERNET_KEY = b"aHd1tFp3V0PcV0ov8Aiz2BAk68WBOEB0KOwNpoKwDPk="`），解密后是标准JSON格式。

### 解密后的JSON结构（推测）

```json
{
  "acupoints": [
    {
      "acupointCode": "BL13",
      "name_zh": "肺俞",
      "start_point": "back_start_point",
      "end_point": "hip_mid",
      "offset_cun": 3.0,
      "direction": "vertical"
    }
  ],
  "acupoints_special": [...],
  "acupoints_XN": [...],
  "acupoints_XN_special": [...]
}
```

每个穴位条目包含：
- `acupointCode`：穴位编码
- `name_zh`：中文名称
- `start_point` / `end_point`：参考基准点（如 `back_start_point`、`hip_mid`、`navel` 等）
- `offset_cun`：偏移寸数
- `direction`：偏移方向（`vertical` 沿基准线 / `right` 右垂直方向）
- `cun`：腹部使用，指定用哪种寸法（`cun1` 上腹 / `cun2` 下腹）

### 关键发现

你的算法位点来训练模型**不是**通过标注穴直接检测穴位，而是：
1. YOLOv11 检测**人体关键点**（肩、髋、膝等解剖标志）
2. 根据**骨度分寸法** + 穴位配置JSON推算出穴位坐标

这是你论文的一个**核心创新点**——不需要对穴位进行标注训练，而是利用中医骨度分寸理论"计算"出穴位位置。

## 问题2：YOLO版本号与算法命名

### YOLO版本确认

从代码 `from ultralytics import YOLO` 和模型文件名 `x-pose.pt`、`neck_x.pt` 来看，你使用的是 **Ultralytics YOLO** 框架。具体版本取决于你安装的 `ultralytics` 包版本。从代码风格和 `YOLO()` API 调用方式来看，兼容 YOLOv8/v11。

**建议**：论文中统一称为 **YOLOv11**（Ultralytics 最新主版本），因为：
- YOLOv11 是 Ultralytics 官方命名的最新版本
- 你的代码使用 `ultralytics` 库，与 YOLOv11 完全兼容
- 学术论文中使用明确的版本号更规范

### 算法命名建议

**YOLOv11-AcupointMap** 是一个合适的名称，理由：
- `YOLOv11`：明确基础模型版本
- `AcupointMap`：体现"穴位映射"的核心思想（关键点→穴位）
- 简洁、易记、有辨识度

其他备选：
- YOLOv11-BCM（Bone-Cun Mapping，骨度分寸映射）
- YOLOv11-APN（Acupoint Positioning Network）

## 问题3：骨度分寸消融实验的开关

**开关位置**：`draw_point.py` 中的骨度分寸计算是**硬编码**的，没有显式的全局开关。

但消融实验可以通过以下方式实现：

### 骨度分寸法的核心代码位置

在 `draw_point.py` 的 `draw_back_acupoints_on_original()` 函数中：

```python
# 背部骨度法 — 第1种：后正中线寸法
CUN_OF_MIDLINE = 22  # 大椎至臀沟 = 22寸
distance_pixels = sqrt((hip_mid_x - neck[0])**2 + (hip_mid_y - neck[1])**2)
PIXELS_PER_CUN = distance_pixels / CUN_OF_MIDLINE

# 第2种：肩部分寸法
CUN_SHOULDER_TO_MIDLINE_2 = 8.5  # 肩峰至后正中线 = 8.5寸
PIXELS_PER_CUN_S = distance_pixels_1 / CUN_SHOULDER_TO_MIDLINE_2

# 第3种：髋部分寸法
CUN_HIP_TO_MIDLINE = 6  # 髋至后正中线 = 6寸
PIXELS_PER_CUN_H = distance_pixels_2 / CUN_HIP_TO_MIDLINE
```

### 消融实验方案

**对照组（无骨度分寸）**：将 `PIXELS_PER_CUN` 替换为固定像素值（如 `PIXELS_PER_CUN = 10.0`），不根据实际人体尺寸自适应计算。

**实验组（骨度分寸法）**：保持现有代码，根据检测到的关键点距离动态计算 `PIXELS_PER_CUN`。

建议在 `draw_point.py` 中添加一个环境变量开关：

```python
USE_BONE_CUN = os.getenv("USE_BONE_CUN", "1") not in {"0", "false", "False"}
if USE_BONE_CUN:
    PIXELS_PER_CUN = distance_pixels / CUN_OF_MIDLINE
else:
    PIXELS_PER_CUN = 10.0  # 固定像素/寸
```

## 问题4：深度相机与2D-3D映射

### 确认：已接入深度相机

是的，你的项目已经完整接入了深度相机。代码位于 `src/depth_camera/`：

- **相机型号**：Deptrum Aurora 900（结构光深度相机）
- **SDK**：`libdeptrum_stream_aurora900.so`（C++ 驱动）
- **核心节点**：`camera_driver_for_deptrumsdk.cpp`

### 深度相机实现的功能

1. **RGB/Depth/IR 图像流发布**（ROS 2 Topic）
2. **点云生成与发布**（`/camera/pointcloud`）
3. **点云处理管线**：
   - 体素滤波（Voxel Grid 降采样）
   - MLS 平滑（Moving Least Squares 表面平滑）
   - 床面去除（基于 Y 轴直方图自动检测并移除按摩床平面）
   - 法线估计（KdTree + PCA，用于获取体表法线方向）
4. **2D→3D 映射服务**（`/camera/pixel_to_points`）：输入像素坐标，返回3D坐标+法线姿态
5. **坐标变换服务**（`/camera/coordinates_to_points`、`/camera/transform_case_to_base`）：坐标系转换
6. **TF 变换发布**：`camera_link → case_link → base_link`

### 是否应加入论文？

**强烈建议加入**。这是你论文区别于纯2D穴位识别论文的关键亮点：

- 从2D像素坐标到3D空间坐标的完整映射链路
- 点云法线估计为按摩姿态提供参考（按摩头垂直于体表）
- 多坐标系TF变换支持机械臂路径规划
- 这使你的工作从"图像识别"升级为"机器人视觉伺服"
